# Security Policy

## Reporting a Vulnerability

We welcome security researchers and users who responsibly report vulnerabilities
they discover in **SmartKNN**. All reports are taken seriously and investigated.

To report a potential vulnerability in SmartKNN, please use the
**“Report a vulnerability”** button on the GitHub Security page:

https://github.com/thatipamula-jashwanth/smart-knn/security

If GitHub reporting is not possible, you may contact the maintainer privately
using the contact information provided in the repository.

---

## When Should I Report a Vulnerability?

Please report a vulnerability if:

- You believe you have discovered a potential security issue in SmartKNN
- You are unsure how a vulnerability might affect SmartKNN or its users
- You have identified a weakness that could lead to data exposure, denial of service,
  or unintended code execution

If in doubt, **report it** — we prefer early notification.

---

## Security Vulnerability Response

Each security report is acknowledged and reviewed by the SmartKNN maintainer
within **5 working days**.

We aim to:
- Confirm the issue
- Assess its impact
- Develop and test a mitigation if required

The reporter will be kept informed of progress when appropriate.

---

## Public Disclosure Timing

Public disclosure is coordinated between the SmartKNN maintainer and the reporter.

Our preference is to disclose vulnerabilities **as soon as a mitigation or fix is
available**, while balancing user safety and responsible disclosure practices.

Disclosure timelines may vary depending on:
- Severity of the issue
- Availability of a fix
- Risk of exploitation
- Coordination requirements

Disclosure may be immediate (especially if already public) or delayed for up to
**90 days** in complex cases.  
For issues with straightforward mitigations, disclosure is typically expected
within **7–14 days**.

---

## Supported Versions

Only the latest released version of SmartKNN is supported for security updates.
